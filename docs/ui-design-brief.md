# 월드씨 UI 디자인 브리프

작성일: 2026-10-12 · 새 디자인 시안 전달 및 비교용

월드씨는 세계의 물고기를 수집하고, 사육·교배하며, 브리딩샵을 수족관으로 성장시키는 세로형 픽셀아트 게임이다. 새 UI는 수조와 물고기를 보는 즐거움을 살리면서, 수색 진행과 수령 가능한 보상을 쉽게 알아볼 수 있어야 한다. 우선 디자인할 화면은 **샵 메인과 원정**이며, 나머지 화면은 같은 시각 규칙을 확장할 수 있도록 정의한다.

## 1. 디자인 범위와 기준

| 항목 | 기준 |
|---|---|
| 기본 화면 | 360×640, 9:16 세로 |
| PC 표시 | 가운데 세로 프레임, 주변 배경은 게임과 어울리는 어두운 색 |
| 장면 | 탑다운 3/4 시점의 브리딩샵·수족관 |
| 아트 | 일정한 픽셀 크기의 2D 픽셀아트 |
| 텍스트 | 한글을 별도 UI 레이어로 표시 |
| 주요 탐색 | 샵 / 사육 / 원정 / 도감 / 상점 |
| 우선 산출물 | 샵 메인, 원정 기본·진행·수령 상태, 공통 UI 부품 |

현재 메인 기준 이미지는 [main-ui-reference.png](reference/main-ui-reference.png)이며, 상세 배치 기준은 [ui-main.md](ui-main.md)에 있다. 전체 기능 목록은 [screens.md](screens.md)를 참고한다. 이 브리프의 개선 제안은 새 시안을 비교하기 위한 요구사항이며, 기존 기준을 변경하는 확정안은 아니다.

## 2. 현재 구현 상태

| 영역 | 현재 상태 | 새 디자인에서 필요한 작업 |
|---|---|---|
| 로그인·닉네임 | Google·Apple·이메일 로그인, 첫 닉네임 입력 UI | 진입 화면과 입력·오류·처리 중 상태 정리 |
| 샵 메인 | 장면, 상단 재화, 간판, 단계 바, 빠른 메뉴, 헌터 카드, 하단 탭 표시 | 화면 위계와 장면 위 라벨 정리 |
| 원정 | 지역·헌터 선택, 반복 횟수, 수색 시작, 진행 현황, 결과 수령 UI 연결 | 정보가 많은 화면을 선택·진행·수령 흐름으로 정리 |
| 입질 | 원정 패널에 입질 UI 연결 | 집중할 수 있는 미니게임 표현과 결과 상태 |
| 사육·도감·상점 | 설명과 ‘준비 중’ 표시 | 후속 화면 디자인 필요 |
| 장면의 수조·문·빠른 메뉴 | 버튼과 라벨 표시, 다수는 화면 이동 동작 미연결 | 눌렀을 때의 목적 화면 정의 |
| 메뉴 | 새로고침·로그아웃 | 우편·설정 등 확장 가능한 메뉴 구성 |

서버 응답으로 재화와 헌터 상태를 표시하지만 경험치·샵 성장 진행률·일부 배지는 임시값을 사용한다. 미리보기는 예시 데이터로 표시한다. 시안에서는 원하는 상태를 그릴 수 있으나, 구현 시 실제 데이터 연결이 필요한 항목을 함께 표시한다.

## 3. 메인 화면 구성

현재 좌표를 비교 기준으로 사용한다. 새 시안에서는 영역 높이를 조정할 수 있지만, 수조·물고기의 식별성과 헌터 상태의 가독성을 함께 확보해야 한다.

| 영역 | 현재 좌표 | 내용 | 디자인 목표 |
|---|---|---|---|
| 상단바 | y=0~38 | 프로필, 프리미엄, 골드, 스태미너, 시간 티켓, 메뉴 | 주요 재화를 빠르게 읽기 |
| 샵 장면 | y=38~500 | 간판, 성장 단계, 수조, 카운터, 문, 빠른 메뉴 | 물고기와 샵 분위기가 먼저 보이기 |
| 헌터 띠 | y=500~576 | 상태 요약, 모두 수령, 최대 4개 카드 | 대기·수색·완료·잠금 구별 |
| 하단 탭 | y=576~640 | 샵 / 사육 / 원정 / 도감 / 상점 | 현재 위치와 다음 이동을 명확히 표시 |

### 상단바

- 프로필: 아바타, 닉네임, 레벨, 경험치.
- 재화: 프리미엄·골드·스태미너·시간 티켓. 스태미너는 현재/최대와 다음 회복 시간을 표시한다.
- 메뉴: 우편 등 새 소식을 나타내는 배지와 메뉴 진입.
- 개선 제안: 긴 닉네임과 큰 재화 숫자가 들어가도 겹치지 않도록 축약·상세 확인 규칙을 정한다. 작은 영역에 모든 정보가 같은 강도로 보이지 않게 우선순위를 둔다.

### 샵 장면

뒷벽의 진열 수조, 중앙 메인 수조, 교배 구역, 아래쪽 치어 수조, 판매 카운터, 시장·길드 입구를 유지한다. 왼쪽에는 출석·복원, 오른쪽에는 가방·친구 빠른 메뉴가 있다.

- 간판은 게임의 이름과 분위기를 전달하고, 단계 바는 샵의 다음 성장 목표를 보여 준다.
- 장면 라벨은 실제 오브젝트와 연결되어야 하며 물고기 관찰을 가리지 않아야 한다.
- 개선 제안: 평상시에는 필요한 이름만 보이고, 선택 시 상세 동작을 보여 주는 방식을 검토한다.
- 손님 대기·교배 완료·성장 완료 알림은 서로 다른 기호와 짧은 문구로 구별한다. 이 알림들은 후속 기능 범위다.
- 1단계 동네 샵부터 4단계 공공 수족관까지 장면이 커져도 공통 UI를 적용할 수 있어야 한다.

물고기 크기의 기존 기준은 메인 수조 몸길이 14~18px, 진열 수조 10~14px, 치어 5~7px이다. 새 배치에서 이 정도 식별성을 유지하고, 상세 화면에서는 개체를 크게 보여 준다.

### 헌터 띠

| 상태 | 필수 정보 | 주요 동작 |
|---|---|---|
| 대기 | 헌터 이름, ‘대기 중’ | 원정 보내기 |
| 수색 중 | 지역, 완료/총 회차, 남은 시간, 진행 바 | 진행 확인 |
| 완료 | 지역, ‘완료 · 수령’ | 결과 확인·수령 |
| 잠금 | 잠금 아이콘, 해금 조건 | 조건 확인 |
| 처리 중 | ‘수령 중…’, 비활성 버튼 | 중복 입력 방지 |

개선 제안: 수령 가능한 카드와 ‘모두 수령’을 먼저 알아볼 수 있게 강조한다. 진행 카드의 배경 그림 위에서도 숫자가 선명해야 한다. 완료·잠금·오류를 색만으로 구분하지 않는다.

### 하단 탭

아이콘과 한글 이름을 함께 표시한다. 선택 탭은 배경·테두리·아이콘 변화로 구별하고, 배지는 중요한 새 결과나 행동이 있을 때 사용한다. 준비 중인 화면은 실제 이용 가능한 화면과 혼동되지 않도록 안내한다.

## 4. 원정 화면

핵심 흐름은 **지역 선택 → 헌터 선택 → 반복 및 옵션 설정 → 수색 시작 → 진행 확인 → 결과 수령**이다. 입질이 발생하면 미니게임 상태로 이어진다.

### 수색 설정

| 항목 | 필요한 표현 |
|---|---|
| 지역 | 이름, 분위기 이미지, 1회 수색 시간, 스태미너 비용, 시간 티켓 필요 여부 |
| 헌터 | 이름, 대기/활동 상태, 선택 가능 여부 |
| 반복 | 횟수 입력, 적용 가능한 한도, 잘못된 입력 안내 |
| 스태미너 부족 | 중단 / 회복 대기 선택 |
| 시작 | 버튼, 처리 중 상태, 시작 성공 또는 오류 안내 |

기획상 반복 한도는 일반 최대 100회, VIP 최대 200회다. 현재 화면 입력·검증에는 200회 상한이 사용되고 일부 안내 문구는 100회를 표시하므로, 구현 단계에서 계정 조건과 문구를 맞춰야 한다. 새 시안은 한도를 계정에 따라 표시할 수 있게 구성한다.

개선 제안: 시작 버튼 가까이에 예상 시간과 소모 재화를 요약하고, 시작 불가 사유를 해당 입력 또는 버튼 옆에 표시한다. 비용 계산 규칙과 실제 지원 범위는 구현 시 확인한다.

### 진행 및 수령

- 진행 카드: 헌터, 지역, 회차, 남은 시간, 스태미너 회복 대기, 정지 사유.
- 수령 영역: 수령 가능한 결과와 입질 대기를 구별하고, 개별 수령·모두 수령을 제공한다.
- 결과 상세의 후속 기획: 물고기, 재화, 아이템, 꽝, 방류 내역을 구분하고 중요한 획득물을 먼저 보여 준다.
- 스크롤이 길어져도 선택 중인 설정과 진행 상태를 이해할 수 있어야 한다. 하단 헌터 띠·탭과 본문이 겹치지 않도록 한다.

### 입질 미니게임

기획 기준으로 물고기 중심 게이지, 좌우 이동하는 바늘, 성공 확률, 입력 동작을 명확히 보여 준다. 대기·진행·성공·실패·만료 상태와 통신 오류를 구별한다. 픽셀 장식이 판정 위치나 숫자를 가리지 않게 하고, 결과 후 원정으로 돌아가는 동작을 제공한다.

## 5. 후속 화면 요구사항

아래는 기존 기획에 따른 후속 디자인 범위다. 현재 완성된 화면으로 취급하지 않는다.

| 화면 | 핵심 콘텐츠 | 중심 동작 |
|---|---|---|
| 사육 목록·수조 상세 | 개체 수, 용도, 수온·염도·수질, 환경 경고, 설비 | 수조 선택·관리 |
| 개체 상세·교배 | 큰 물고기 이미지, 어종·모프·성장 정보, 부모 선택 | 교배·이동·판매 |
| 도감 | 어종·모프, 발견 여부, 보전 상태, 달성률 | 찾기·상세 보기 |
| 상점 | 장비·아이템·외형, 가격, 보유 재화, 구매 조건 | 비교·구매 |
| 시장·길드 | 거래 상태, 가입·멤버·퀘스트, 복원 진행 | 거래·협동 |
| 가방·출석·친구 | 수량, 받을 보상, 요청·방문 | 사용·수령·교류 |
| 프로필·설정 | 성장 정보, 알림·입질 옵션 | 확인·설정 변경 |

## 6. 시각 방향과 공통 규칙

현재 방향은 어두운 청록 UI, 금색 강조, 나무·유리·물빛이 있는 픽셀 수족관이다. 새 시안은 이 분위기를 발전시키거나 다른 팔레트를 제안할 수 있다. 화면마다 프레임·그림자·버튼 규칙이 일관되어야 한다.

| 용도 | 현재 색상 | 사용 방향 |
|---|---|---|
| 기본 배경 | `#101D26` | 장면과 패널을 받쳐 주는 어두운 색 |
| 패널 | `#1C2A37` | 본문과 카드 배경 |
| 탭 | `#193447` | 하단 탐색 |
| 주요 글자 | `#F2F5F6` | 이름·숫자·본문 |
| 보조 글자 | `#85A0A7` | 설명·부가 정보 |
| 금색 | `#E8B248` | 재화·보상·핵심 동작 |
| 물빛 | `#8FDEE5` | 선택·초점 표현 |
| 알림 | `#E5484D` | 주의가 필요한 새 상태 |

- 현재 한글 폰트는 Galmuri11이며 일부 작은 글자에 Galmuri9를 사용한다. 새 시안은 360px 폭에서 실제 읽을 수 있는 크기를 제시한다.
- 제목·본문·보조 숫자에 크기와 색의 위계를 둔다. 자주 확인하는 숫자를 장식보다 선명하게 표시한다.
- 픽셀 이미지는 일정한 픽셀 크기를 유지한다. 기존 문서는 정수 배율 확대를 목표로 하지만 현재 웹 프레임은 화면 크기에 비례하므로, 실제 기기에서 픽셀 선명도를 확인해야 한다.
- 터치 영역은 실제 표시 크기 기준 최소 44×44 CSS px를 목표로 한다. 보이는 아이콘이 작으면 주변 여백으로 확보한다.
- 선택·잠금·오류는 아이콘 또는 문구를 함께 사용한다. 키보드 초점도 보이게 한다.
- 기기 하단 안전 영역과 브라우저 높이 변화로 주요 버튼이 잘리지 않게 한다.

## 7. 공통 UI 부품과 상태

시안에는 재화 표시, 기본·주요·비활성 버튼, 헌터 카드, 탭, 배지, 진행 바, 입력·선택 컨트롤, 상세 패널, 알림을 포함한다. 각 부품은 다음 상태를 함께 제시한다.

| 상태 | 필요한 안내 |
|---|---|
| 기본·선택·눌림 | 현재 위치와 입력 반응 |
| 잠금·사용 불가 | 이유와 해금 조건 |
| 불러오는 중·처리 중 | 진행 표시와 중복 입력 방지 |
| 빈 목록 | 빈 이유와 가능한 다음 행동 |
| 오류 | 실패 내용과 재시도 |
| 성공·수령 완료 | 얻은 결과와 다음 행동 |
| 미리보기 | 예시 데이터임을 표시 |

## 8. 새 디자인 전달 체크리스트

1. **샵 메인 1장**: 상단 재화·샵 장면·헌터 띠·하단 탭을 모두 포함한다.
2. **헌터 상태 예시**: 대기·수색·완료·잠금을 같은 화면에서 비교할 수 있게 한다.
3. **원정 3장**: 수색 설정, 진행 중, 결과 수령 상태를 제시한다.
4. **입질 예시**: 미니게임과 결과 화면을 제시한다.
5. **UI 부품 모음**: 버튼·카드·탭·입력·배지·폰트·색상 기준을 제시한다.
6. **레이어 분리**: 장면 이미지, 장식 프레임, 아이콘, UI 글자를 구분한다. 글자가 포함된 완성 이미지와 별도 텍스트 없는 에셋을 구별한다.
7. **변경 설명**: 기존 기준에서 바뀐 위치·크기·탐색 흐름과 새로 필요한 기능을 적는다.

첫 비교는 샵 메인과 원정 화면으로 진행한다. 전체 후속 화면을 모두 완성하기 전에 공통 스타일과 화면 위계를 먼저 결정할 수 있다.

## 9. 시안 평가 기준

- 첫 화면에서 샵의 분위기와 수조·물고기가 잘 보이는가?
- 수색 중인 헌터와 수령 가능한 결과를 즉시 구별할 수 있는가?
- 360px 폭에서 한글·시간·재화 숫자를 읽을 수 있는가?
- 긴 닉네임·큰 재화 값·잠금 조건이 겹치거나 잘리지 않는가?
- 주요 버튼을 누르기 쉽고, 하단 탭과 본문이 겹치지 않는가?
- 샵과 원정이 같은 게임의 화면처럼 보이는가?
- 새 디자인에서 추가한 기능과 기존 기능의 표현 변경이 구분되어 있는가?
